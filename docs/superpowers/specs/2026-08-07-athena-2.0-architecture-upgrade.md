# Athena 2.0 Multi-Agent Institutional Trading Architecture - Design Spec

**Date:** 2026-08-07  
**Project:** Athena Crypto Agent Ecosystem  
**Status:** Architecture Upgrade Specification  

---

## 1. Executive Summary

Athena 2.0 evolves Athena from a multi-agent screening and signal engine into an **institutional-grade, resilient autonomous trading ecosystem**. This upgrade addresses the 11 architectural gaps identified during self-auditing, hardening the system against market volatility, execution slippage, RPC downtime, and agent signal conflicts.

---

## 2. Detailed Architectural Upgrades

### 2.1 Advanced Risk Engine & Real-Time Circuit Breakers (`RiskEngineV2`)
- **Per-Asset Exposure Cap:** Max 10% of portfolio in any single token.
- **Per-Chain Exposure Cap:** Max 40% per blockchain ecosystem (Solana, Base, Ethereum L1, Polygon).
- **Narrative Correlation Guard:** Maximum 3 positions in tokens sharing identical social/sector tags (e.g. AI, Doge-memes, Polifi).
- **Volatility Sizing:** Dynamic position size calculations using ATR (Average True Range) and Kelly Criterion.
- **Kill-Switch Trigger:** Halts all automated trading if daily drawdown exceeds 5% or if 3 consecutive trades hit Stop-Loss within 1 hour.

### 2.2 Strategy Backtesting Engine (`BacktesterEngine`)
- **Historical Data Replay:** Replays historical 1-minute OHLCV, DEX liquidity logs, and social sentiment archives against Swarm Consensus rules.
- **Parametric Optimization:** Automatically tests and recommends TP/SL thresholds and trailing stop distances per token class (Memes vs Perps vs LPs).

### 2.3 Resilient Data Pipeline & Multi-RPC Failover (`RPCFailoverManager`)
- **Active RPC Pool:** Maintains dynamic latency and success-rate metrics across 3+ RPC providers per chain (e.g. Alchemy, QuickNode, Helius, Triton).
- **Stale Price Protection:** Rejects price updates older than 30 seconds.
- **Crash Recovery:** Reconstructs in-memory position state from SQLite/Prisma trade audit logs upon process restart.

### 2.4 Execution Safety & MEV Protection (`MEVExecutionGuard`)
- **Private Tx Routing:** Routes EVM transactions through Flashbots / Private RPCs to eliminate front-running and sandwich attacks. Routes Solana txs via Jito Bundles with priority tips.
- **Pre-Flight Simulation:** Simulates tx outcome on-chain before signing.
- **Idempotency Guard:** Nonce locking and transaction hash tracking to guarantee single execution.

### 2.5 Consensus & Agent Reputation Engine (`SwarmConsensusV2`)
- **Dynamic Reputation Scoring:** Sub-agent weights automatically adjust based on rolling 30-day win rate and profit factor.
- **Weighted Consensus Voting:** Resolves conflicting calls across agents using agent reputation score.
- **Deduplication:** Prevents duplicate signal alerts within a 2-hour window.

### 2.6 Incident Response & Health Monitoring (`HealthWatcherService`)
- **Agent Heartbeats:** Sub-agents ping central health monitor every 60 seconds.
- **Auto-Recovery:** Automatically restarts crashed background sub-agents.
- **Real-Time Telemetry:** Sends instant alert cards to Discord/Telegram on system anomalies.

### 2.7 Post-Trade Analytics & Performance Attribution (`AnalyticsService`)
- **Performance Breakdown:** Computes net PnL, Win Rate, Profit Factor, and Sharpe Ratio categorized by agent, chain, and confidence score.
- **Fee Attribution:** Tracks gas fees and MEV tips versus gross profits.

### 2.8 Emergency Override & Permission Controls (`HubV2`)
- **`/closeall` Panic Command:** One-click emergency market close of all open positions and global screening pause.
- **Multi-Tier Authorization:** Requires explicit user confirmation modal for orders > 1 SOL or 500 USDC.

### 2.9 Market Regime Classification (`MarketRegimeFilter`)
- **Macro Market Detector:** Categorizes market state into `TRENDING_BULL`, `TRENDING_BEAR`, `SIDEWAYS_CHOP`, and `HIGH_VOLATILITY`.
- **Adaptive Strategy Rules:** Pauses trend-following perps during chop; widens LP tick ranges during high volatility.

### 2.10 Security & On-Chain Simulation
- **AES-256 Key Encryption:** Encrypts local burner wallet private keys at rest.
- **Full Audit Trail:** Timestamped record of every signal, confidence score breakdown, execution parameters, and exit reasons stored in SQLite.

### 2.11 Telegram Bridge & REST API (`TelegramBridge` & `APIServer`)
- **Unified Telegram Mirror:** Mirrors Discord call signals and trade logs to a private Telegram channel.
- **REST Telemetry API:** Lightweight HTTP API exposing system status, health, and current positions.

## 3. Implementation Phases

- **Phase 1:** Core Safety & Emergency Controls (`RiskEngineV2`, `/closeall`, Pre-Flight Tx Simulation, Multi-RPC Failover).
- **Phase 2:** Consensus & Quality Gates (`SwarmConsensusV2` Reputation Scoring, Market Regime Filter, Health Watcher).
- **Phase 3:** Telemetry, Backtesting & Integration (`BacktesterEngine`, Analytics Service, Telegram Bridge & REST API).
